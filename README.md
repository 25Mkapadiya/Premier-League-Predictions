# PL Forecast — Premier League Predictions

A dark, audit-friendly **2026/27 Premier League forecasting dashboard**. The site combines a football score model with timestamped recent form, schedule context, optional xG/lineup feeds, bookmaker consensus and a walk-forward trained ensemble.

## What changed in v3

- server-side prediction snapshots generated by GitHub Actions
- forecasts freeze at kickoff and are graded later without hindsight
- dynamic opponent-adjusted recent form
- rest and fixture-congestion adjustments
- Football-Data shots / shots-on-target enrichment
- small, capped player-availability proxy
- optional Sportmonks xG enrichment
- optional API-Football injury / confirmed-lineup context
- optional multi-bookmaker fair-probability consensus
- time-ordered ensemble training with a later untouched holdout
- Brier score and log loss on the Results page
- score-grid realignment so 1X2, BTTS, totals and correct score stay coherent
- visible per-fixture engine, data quality and signal agreement

## Always works without secrets

The site still works with no paid provider configured. It falls back through the strongest available timestamp-safe layers rather than inventing missing data.

## Optional GitHub Secrets

Add these at **Settings → Secrets and variables → Actions**:

- `ODDS_API_KEY` — The Odds API bookmaker consensus
- `SPORTMONKS_API_TOKEN` — post-match team xG enrichment
- `API_FOOTBALL_KEY` — near-kickoff injuries and confirmed lineups

No secret is shipped to GitHub Pages.

## Refreshing data

`.github/workflows/refresh-results.yml` runs hourly and can also be run manually:

**Actions → Refresh Premier League prediction data → Run workflow**

The job refreshes fixtures/results, adds match statistics and optional enrichments, preserves disappearing pre-match evidence, builds future predictions, freezes kicked-off forecasts and commits `data/live.js`.

The website refresh button only reloads the newest committed snapshot; it does not expose GitHub credentials in the browser.

## Training the learned ensemble

Run:

**Actions → Train prediction ensemble → Run workflow**

The trainer uses a strict chronological split and writes `data/trained_model.json` only if training completes successfully. The production engine automatically starts using that model when `enabled` is true.

See [`docs/ACCURACY.md`](docs/ACCURACY.md) for the exact evaluation policy.

## Model policy

The structural model remains the anchor: venue-specific attack/defense, Elo, Poisson score probabilities, Dixon-Coles low-score correction and promoted-team translation.

Recent/context signals are capped and shrunk. Missing xG, lineups or odds do not silently become guessed values. New features should remain secondary until a holdout test shows they improve Brier score or log loss.

This is an independent fan project and is not affiliated with the Premier League or its clubs. Predictions are estimates, not betting advice.
